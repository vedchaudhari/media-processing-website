# 15. Retry Button for Failed Pipeline Stages

**Status:** ✅ Done

- **New `retryStage(videoId, stage)`** API call plus `RetryStageName`/`RetryStageResponse` types, hitting the new `POST /api/videos/:videoId/retry/:stage` backend endpoint (see backend entry 22).
- **New `RetryButton` component** in `VideoDetail.tsx`, added inside all three existing red "failed" panels — Interactive Transcript, AI Insights, and Ask AI indexing. Uses simple local loading/error state (`try/catch/finally`), matching the existing hand-rolled pattern already used by the Ask-AI chat in this same file rather than introducing a new state-management approach.
- **Resumes polling on success:** the page's `useQuery` stops its 3s poll once a stage is `"failed"` (its `refetchInterval` only re-arms for `pending`/`processing`), so the button calls the query's `refetch()` after a successful retry to immediately reflect the stage moving back to `pending`/`processing` — otherwise the retry would appear to do nothing until an unrelated refresh.
- **Errors shown inline** next to the button (e.g. the backend's 409 "transcript must finish successfully first" message for AI/Ask-AI retries) rather than a separate banner.
