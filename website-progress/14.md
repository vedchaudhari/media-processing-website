# 14. Cancel Upload UI

**Status:** ✅ Done

- **`uploadToStorage` gains an `AbortSignal`:** the XHR-based upload (`api.ts`) now accepts an optional `signal` and wires `signal.addEventListener("abort", () => xhr.abort())`. Also adds the previously-missing `xhr.onabort` handler — aborting an XHR fires neither `onload` nor `onerror`, so without it the upload promise would have hung forever on cancel.
- **New `UploadAbortedError`** (`name: "AbortError"`) lets callers distinguish "the user cancelled this" from a genuine network failure, instead of both paths landing in the same generic catch block.
- **New `cancelUpload(videoId)`** API call — `POST /api/videos/:videoId/cancel-upload`, telling the backend to give up on and delete the reserved record (client-side abort alone only stops the browser's request; the server doesn't otherwise learn about it).
- **Upload page (`app/upload/page.tsx`):** new `"cancelling"` phase and a Cancel link, shown only while the file is actively uploading (hidden once `"finalizing"` starts — the PUT has already finished at that point, so there's nothing left on the wire to stop). Clicking it aborts the in-flight XHR, calls `cancelUpload`, then resets the form with no error banner — the `AbortError` case is explicitly short-circuited in `handleUpload`'s catch block so it doesn't fall through to the generic "Upload failed" message.
